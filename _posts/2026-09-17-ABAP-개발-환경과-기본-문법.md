# 1. ABAP이란?

ABAP은 SAP 시스템에서 업무 로직을 구현하기 위해 사용하는 프로그래밍 언어이다.

SAP ERP / S/4HANA 환경에서 ABAP 프로그램은 일반적으로 Application Server의 ABAP Runtime에서 실행된다.

기본적인 구조는 다음과 같다.

```text
사용자
  ↓
SAP GUI / Fiori
  ↓
SAP Application Server
  ↓
ABAP Runtime
  ↓
Database
```

Basis 컨설턴트 입장에서는 ABAP 개발 자체보다도 다음과 같은 실행 구조를 이해하는 것이 중요하다.

- 어떤 프로그램이 실행되는가?
- 어떤 Application Server에서 실행되는가?
- 어떤 DB를 사용하는가?
- 어떤 사용자가 실행하는가?
- 실행 시간이 오래 걸리는 이유는 무엇인가?
- Transport Request는 무엇인가?

# 2. ABAP Repository

ABAP 프로그램과 관련된 개발 객체는 SAP Repository에 저장된다.

대표적인 Repository Object는 다음과 같다.

| Object | 설명 |
|---|---|
| Program | ABAP 프로그램 |
| Class | ABAP 객체지향 클래스 |
| Function Module | 함수 모듈 |
| Interface | 인터페이스 |
| Dictionary Object | 테이블, 데이터 요소 등 |
| CDS View | CDS 기반 데이터 모델 |
| Enhancement | 표준 프로그램 확장 |
| Transaction Code | 프로그램 실행을 위한 트랜잭션 |

예를 들어 SE38에서 생성하는 ABAP 프로그램 역시 Repository Object이다.

# 3. SAP 개발 시스템의 기본 흐름

일반적인 SAP 시스템에서는 개발 변경사항이 다음과 같이 이동한다.

```text
DEV
 ↓
Transport Request
 ↓
QAS
 ↓
PRD
```

개발자가 DEV에서 ABAP 프로그램을 수정하면 Transport Request에 변경사항이 기록된다.

이 Transport Request를 이용하여 QAS와 PRD로 변경사항을 이관한다.

Basis 컨설턴트에게 Transport는 매우 중요한 영역이다.

# 4. 가장 기본적인 ABAP 프로그램

가장 단순한 ABAP 프로그램은 다음과 같다.

```abap
REPORT zday01_basic.

WRITE: / 'Hello ABAP'.
```

## REPORT

```abap
REPORT zday01_basic.
```

현재 프로그램이 `ZDAY01_BASIC`이라는 Executable Program임을 선언한다.

일반적으로 고객 개발 프로그램은 `Z` 또는 `Y` 네임스페이스를 사용한다.

## WRITE

```abap
WRITE: / 'Hello ABAP'.
```

화면에 문자열을 출력한다.

`/`는 새로운 줄에서 출력한다는 의미이다.

---

# 5. DATA 선언

ABAP에서 변수를 선언할 때 `DATA`를 사용한다.

```abap
DATA: lv_name TYPE string,
      lv_role TYPE string.

lv_name = 'ABAP Learner'.
lv_role = 'Basis Consultant'.

WRITE: / 'Name:', lv_name.
WRITE: / 'Role:', lv_role.
```

여기서 중요한 개념은 다음과 같다.

```text
DATA
 ↓
변수 선언

TYPE
 ↓
데이터 타입 지정

=
 ↓
값 할당
```

---

# 6. IF 조건문

ABAP에서도 조건에 따라 프로그램의 실행 흐름을 변경할 수 있다.

```abap
DATA lv_status TYPE string.

lv_status = 'ACTIVE'.

IF lv_status = 'ACTIVE'.
  WRITE: / 'User is active'.
ELSE.
  WRITE: / 'User is inactive'.
ENDIF.
```

기본 구조는 다음과 같다.

```abap
IF 조건.
  실행문.
ELSE.
  실행문.
ENDIF.
```

---

# 7. DO 반복문

같은 작업을 반복할 때 `DO`를 사용할 수 있다.

```abap
DO 5 TIMES.
  WRITE: / sy-index.
ENDDO.
```

결과:

```text
1
2
3
4
5
```

여기서 `sy-index`는 현재 반복 횟수를 나타내는 시스템 필드이다.

---

# 8. SY-* 시스템 필드

ABAP에는 SAP 시스템에서 자동으로 관리하는 여러 시스템 필드가 존재한다.

대표적인 예:

```text
sy-index
sy-subrc
sy-datum
sy-uzeit
sy-uname
```

특히 Basis/ABAP 분석에서 자주 접하게 되는 것이 `sy-subrc`이다.

예를 들어 데이터 조회나 특정 명령 실행 후 성공 여부를 확인할 때 사용할 수 있다.

```abap
IF sy-subrc = 0.
  WRITE: / 'Success'.
ELSE.
  WRITE: / 'Failed'.
ENDIF.
```

# 9. 실습 — 첫 번째 ABAP 프로그램

## Step 1. SE38 실행

SAP GUI에서 다음 트랜잭션을 실행한다.

```text
SE38
```

## Step 2. 프로그램 생성

프로그램 이름:

```text
ZDAY01_BASIC
```

프로그램을 생성한다.

---

## Step 3. 다음 프로그램 작성

```abap
REPORT zday01_basic.

DATA: lv_name   TYPE string,
      lv_role   TYPE string,
      lv_status TYPE string.

lv_name   = 'ABAP Learner'.
lv_role   = 'Basis Consultant'.
lv_status = 'ACTIVE'.

WRITE: / 'Name  :', lv_name.
WRITE: / 'Role  :', lv_role.
WRITE: / 'Status:', lv_status.

IF lv_status = 'ACTIVE'.
  WRITE: / 'User is active'.
ELSE.
  WRITE: / 'User is inactive'.
ENDIF.
```

# 11. Debugging 실습

ABAP 프로그램을 분석할 때 Debugger는 매우 중요한 도구이다.

프로그램의 실행문에 Breakpoint를 설정한다.

예:

```abap
lv_name   = 'ABAP Learner'.
lv_role   = 'Basis Consultant'.
lv_status = 'ACTIVE'.
```

Breakpoint를 설정한 후 프로그램을 실행한다.

Debugger에서 다음 값을 확인한다.

```text
lv_name
lv_role
lv_status
sy-subrc
sy-index
```

이를 통해 프로그램이 실제로 어떤 값을 가지고 실행되는지 확인할 수 있다.

# 12. Basis 컨설턴트 관점에서 ABAP 보기

ABAP 개발자가 아니라 Basis 컨설턴트라고 하더라도 ABAP 프로그램의 기본 구조를 이해하면 시스템 장애나 성능 문제를 분석하는 데 도움이 된다.

ABAP 프로그램을 만났을 때 다음 질문을 한다.

### ① 어떤 프로그램인가?

```text
Program Name
```

### ② 어떤 Transaction에서 실행되는가?

```text
Transaction Code
```

### ③ 어떤 DB Table을 조회하는가?

```text
SELECT
 ↓
Database Table
```

### ④ 어떤 사용자가 실행하는가?

```text
SY-UNAME
```

### ⑤ 어느 Application Server에서 실행되는가?

```text
Application Server
```

### ⑥ 실행 시간이 오래 걸린다면?

다음 영역을 생각한다.

```text
ABAP Logic
    ↓
SQL
    ↓
Database
    ↓
Application Server
    ↓
System Resources
```

### ⑦ 변경사항은 어떤 Transport에 들어있는가?

```text
Development
    ↓
Transport Request
    ↓
QAS
    ↓
PRD
```

# 13. 오늘 배운 핵심 문법

| 문법 | 의미 |
|---|---|
| `REPORT` | Executable ABAP 프로그램 선언 |
| `DATA` | 변수 선언 |
| `TYPE` | 데이터 타입 지정 |
| `WRITE` | 화면 출력 |
| `IF` | 조건문 |
| `ELSE` | 조건이 거짓일 때 실행 |
| `ENDIF` | IF 종료 |
| `DO` | 반복문 |
| `ENDDO` | DO 종료 |
| `sy-index` | 반복 횟수 |
| `sy-subrc` | 이전 처리 결과 |
| `SE38` | ABAP 프로그램 실행/관리 |
| `F8` | 프로그램 실행 |

# 15. 오늘의 핵심 정리

### ABAP

SAP Application Server에서 업무 로직을 구현하는 프로그래밍 언어

### REPORT

실행 가능한 ABAP 프로그램을 선언

### DATA

변수를 선언

### WRITE

화면에 값을 출력

### IF

조건에 따라 프로그램 흐름을 제어

### DO

반복 실행

### SY-*

SAP Runtime이 제공하는 시스템 필드

### Repository

ABAP 개발 객체가 관리되는 SAP 저장소

### Transport

DEV에서 개발한 변경사항을 QAS/PRD로 이관하는 체계
