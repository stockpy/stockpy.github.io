# SAML 2.0 — ACS (Assertion Consumer Service) 이해 가이드

## ACS 란?

ACS(Assertion Consumer Service)는 **SAML 2.0 프로토콜에서 IdP가 인증 응답(SAML Response)을 SP에게 POST하는 엔드포인트 URL**입니다. IdP가 "이 사용자가 인증되었습니다"라는 SAML Assertion을 보낼 목적지입니다.

---

## SAML 인증 흐름과 ACS의 위치

```
사용자 → SP 로그인 요청 → IdP로 리다이렉트 → 인증 완료 → ACS URL에 SAML 응답 POST → SP가 응답 검증 → 세션 생성
```

단계별로 풀어보면:

```
1. 사용자 → SAP 앱(S/4HANA) 접속
2. SP → IdP로 인증 요청 (SAML AuthnRequest)
3. 사용자 → IdP에서 로그인 (ID/PW + MFA)
4. IdP → ACS 엔드포인트로 인증 응답 전송 (SAML Response)  ← ACS가 여기에서 동작
5. SP의 ACS → SAML 응답 검증 → 사용자 인증 완료
```

ACS URL을 등록하지 않으면 IdP가 응답을 보낼 곳을 모르므로 **SSO가 작동하지 않습니다**.

---

## IdP 관리 콘솔에서 ACS URL 설정

IdP 관리 콘솔(예: Azure AD 엔터프라이즈 애플리케이션)에서 SP를 등록할 때 입력하는 항목:

```
IdP 관리 콘솔 (예: Azure AD 엔터프라이즈 애플리케이션)
├── Identifier (Entity ID)  →  SP Entity ID를 입력
└── Reply URL (ACS URL)     →  ACS URL을 입력
```

| IdP 설정 항목 | SP에서 대응 값 | 설명 |
|---|---|---|
| **Identifier (Entity ID)** | SP의 고유 식별자 | SP를 구분하는 ID |
| **Reply URL (ACS URL)** | `<AssertionConsumerService Location="...">` | SAML 응답을 보낼 URL |

---

## ACS URL 확인 방법

### SAP IAS의 경우

IAS Administration Console → **Tenant SAML 2.0 Configurations**에서 메타데이터 XML 다운로드 후 `<AssertionConsumerService>` 태그의 `Location` 속성 확인.

```xml
<ns3:AssertionConsumerService
  index="0" isDefault="true"
  Binding="urn:oasis:names:tc:SAML:2.0:bindings:HTTP-POST"
  Location="https://<tenant>.accounts.ondemand.com/saml2/sp/acs/..." />
```

---

## IdP-Initiated SSO 시 ACS URL 파라미터 추가

IdP-Initiated SSO(unsolicited SAML 응답)를 사용하려면 ACS URL에 파라미터를 추가해야 합니다.

```
https://<ACS endpoint URL>?sp=<sp_name>&index=<index_number>
```

| 파라미터 | 설명 |
|---|---|
| `sp` | Service Provider의 Entity ID (**필수**) |
| `index` | 여러 ACS 엔드포인트가 있을 때 기본이 아닌 경우 필요 |

### 설정 위치

| 시나리오 | 설정 위치 |
|---|---|
| **단일 Corporate IdP** | Corporate IdP 측 ACS 엔드포인트에 `?sp=<sp_name>` 추가 |
| **여러 Corporate IdP** | ACS 엔드포인트에 `?sp=<sp_name>&index=<index_number>` 추가 |

## SingleID에 IAS를 SP로 등록 시 ACS 입력

삼성 SDS SingleID에 SAP IAS를 SP로 등록할 때 전달하는 정보:

| SingleID 등록 항목 | IAS 대응 값 | 설명 |
|---|---|---|
| **Service Name** | IAS 테넌트 식별자 | 영문 12자 이내 |
| **Service Name (KR)** | 한글 서비스 이름 | 50자 이내 |
| **Service URL (ACS)** | IAS의 ACS URL | `https://<tenant>.accounts.ondemand.com/saml2/sp/acs/...` |
| **Authentication Request Sign** | Yes/No | Yes면 IAS의 CSR 파일(SP 공개 키) 전달 |
| **수신할 사용자 정보** | First Name, Last Name, Email 등 | 필요 속성 명시 |

## ACS와 MFA 정책

SAPGUI SSO + MFA 환경에서 MFA 정책은 **ACS URL이 등록된 대상 서비스**에 적용됩니다.

| 설정 항목 | 내용 |
|---|---|
| **대상 서비스** | IAS ACS URL (`https://<tenant>.accounts.ondemand.com/saml2/sp/acs/...`) |
| **MFA 정책** | 해당 서비스에 접근하는 모든 인증에 MFA 강제 |
| **MFA 방식** | SMS, mOTP, TOTP, 생체 등 조직 정책 기준 |

MFA는 IdP(SingleID) 레이어에서 enforcement되며, SLS/IAS/SLC/SAPGUI는 MFA를 인지하지도, 처리하지도 않습니다.

## 흔한 실수

### Entity ID와 ACS URL 혼동

**Entity ID**와 **ACS URL**을 같은 값으로 설정하면 작동하는 경우가 많지만, 개념적으로 다릅니다.

| 구분 | Entity ID | ACS URL |
|---|---|---|
| **역할** | SP를 식별하는 고유 ID | SAML 응답을 보낼 URL |
| **형식** | URI 형식 (`urn:...` 또는 `https://...`) | HTTP(S) URL |
| **용도** | 메타데이터에서 SP 식별 | 실제 SAML Response 전송 목적지 |

### ACS URL 잘못 입력 시 증상

IdP 설정에서 ACS URL을 잘못 입력하면 인증 후 다음 에러가 발생합니다:

- **Invalid Response** — SP가 SAML 응답을 받지 못함
- **No ACS URL** — IdP가 응답을 보낼 엔드포인트를 찾지 못함
