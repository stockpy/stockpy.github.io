# S/4HANA SSO 시나리오 — Fiori, WebGUI, SAPGUI 인증 흐름 비교

## 개요

S/4HANA에 접근하는 세 가지 방식(Fiori, WebGUI, SAPGUI)은 **프로토콜**과 **SSO 메커니즘**이 근본적으로 다릅니다. 이 문서에서는 각 접근 방식의 인증 흐름과 IAS Application 설정 필요성을 비교합니다.

---

## 접근 방식 비교

| 구분 | SAPGUI | Fiori | WebGUI |
|---|---|---|---|
| **접근 방식** | 클라이언트 앱 (SAP GUI for Windows) | 웹 브라우저 | 웹 브라우저 |
| **프로토콜** | SAP GUI (RFC/SNC) | HTTP/S (REST/OData) | HTTP/S (Applet) |
| **SAML 2.0 지원** | ❌ 직접 불가 | ✅ 네이티브 지원 | ✅ 지원 |
| **주요 SSO 방식** | Kerberos, Logon Ticket, SLS(X.509) | SAML 2.0 (IAS 경유) | SAML 2.0, Logon Ticket |
| **IAS 연동 방법** | SLS(Secure Login Service) 브리지 필요 | 직접 SAML SP 연동 | 직접 SAML SP 연동 |
| **추천 여부** | 온프레미스 데스크톱 작업 | **표준 권장** | 레거시 (점차 폐기) |

---

## 시나리오 1: 사용자 → Fiori / WebGUI 접속 시

### 인증 흐름

```
사용자 → 브라우저 → Fiori/WebGUI(SP) → IAS(IdP/SP) → Corporate IdP(IdP)
                                                          ↓
                                                 SAML Assertion
                                                          ↓
사용자 ← 브라우저 ← Fiori/WebGUI ← IAS ←─────────────────(SAML Response)
```

> **IAS(IdP/SP)** — Fiori/WebGUI에게는 **IdP**이고, Corporate IdP에게는 **SP**입니다.

### 단계별 동작

| 단계 | 동작 |
|---|---|
| 1 | 브라우저에서 Fiori Launchpad 또는 WebGUI URL 접속 |
| 2 | Fiori/WebGUI → IAS로 SAML AuthnRequest 전송 |
| 3 | IAS → Corporate IdP로 인증 리다이렉트 |
| 4 | 사용자는 Corporate IdP에서 인증 (ID/PW + MFA) |
| 5 | Corporate IdP → ACS URL로 SAML Assertion POST |
| 6 | IAS가 Assertion 검증 → S/4HANA가 이해하는 형태로 변환 |
| 7 | IAS → Fiori/WebGUI로 SAML Response 전송 |
| 8 | Fiori/WebGUI가 응답 검증 → 세션 생성 → 접근 허용 |

### IAS Application 설정

| 항목 | Fiori | WebGUI |
|---|---|---|
| Application 생성 | ✅ 필요 | ✅ 필요 |
| ACS URL | Fiori Launchpad 로그인 페이지 URL | WebGUI 로그인 페이지 URL |
| SAML 바인딩 | HTTP-Redirect / HTTP-Post | HTTP-Redirect / HTTP-Post |

**핵심:** 표준 SAML 2.0 흐름. IAS Administration Console에서 S/4HANA를 SAML 2.0 Application으로 등록하고, S/4HANA의 메타데이터 XML을 업로드하면 됩니다.

## 시나리오 2: 사용자 → SAPGUI 접속 시

### 인증 흐름

```
사용자 → SAPGUI → SLC(클라이언트) → SLS(BTP/SP) → IAS(IdP/SP) → Corporate IdP(IdP)
                                                                        ↓
                                                               SAML Assertion
                                                                        ↓
사용자 ← SAPGUI ← SLC ← SLS ←───────────────────────(X.509 인증서)
```

> **SLS(BTP/SP)** — IAS에게는 **SP**로 동작합니다.
> **IAS(IdP/SP)** — SLS에게는 **IdP**이고, Corporate IdP에게는 **SP**입니다.

### 단계별 동작

| 단계 | 동작 |
|---|---|
| 1 | SAPGUI 실행 |
| 2 | SLC가 X.509 인증서 필요 감지 (또는 인증서 만료) |
| 3 | SLC → SLS(BTP)로 인증 요청 |
| 4 | SLS → IAS로 SAML AuthnRequest 전송 |
| 5 | IAS → Corporate IdP로 인증 리다이렉트 |
| 6 | SLC 내장 browser 자동 팝업 → Corporate IdP 로그인 화면 |
| 7 | 사용자는 ID/PW + MFA 인증 |
| 8 | Corporate IdP → ACS URL로 SAML Assertion POST |
| 9 | IAS가 Assertion 검증 → SLS로 인증 결과 전달 |
| 10 | SLS → X.509 인증서 발급 (기본 12시간) |
| 11 | SLC → SAPGUI에 인증서 제공 |
| 12 | SAPGUI → SAP Backend SNC/X.509 인증 → 로그인 성공 |

### IAS Application 설정

| 항목 | SAPGUI (SLS) |
|---|---|
| Application 생성 | ✅ 필요 (Corporate IdP 프록시 모드일 경우) |
| ACS URL | SLS의 ACS URL (`https://<tenant>.accounts.ondemand.com/saml2/sp/acs/...`) |
| SAML 바인딩 | HTTP-Redirect |

**핵심:** SAML은 IAS ↔ Corporate IdP 간에만 사용되며, SAPGUI에는 X.509 인증서가 전달됩니다. MFA는 Corporate IdP 레이어에서 enforcement되며, SLS/IAS/SLC/SAPGUI는 MFA를 인지하지도, 처리하지도 않습니다.

## IAS Application 구성 필요성

### SAPGUI + SLS 시나리오에서 IAS Application이 필요한 경우

| 시나리오 | IAS Application 필요? | 이유 |
|---|---|---|
| SLS + IAS 로컬 사용자 | ❌ 불필요 | SLS가 IAS 테넌트 메타데이터 직접 사용 |
| SLS + IAS 프록시 + Corporate IdP | ✅ **필수** | SLS를 SP로 등록하고 Corporate IdP 위임 필요 |

Corporate IdP를 사용하지 않는 단순한 SLS 구성이라면 IAS Application 생성은 생략 가능합니다. SLS Web UI에서 IAS 연결 설정만 완료하면 됩니다.

### Fiori / WebGUI 시나리오

**IAS Application 구성은 항상 필요합니다.** Fiori Launchpad와 WebGUI는 각각 별도의 SAML 2.0 Application으로 등록되어야 합니다.

## 핵심 차이점 요약

| 구분 | Fiori / WebGUI | SAPGUI |
|---|---|---|
| **SAML 직접 사용** | ✅ 브라우저가 SAML 응답 처리 | ❌ SAML은 IAS ↔ Corporate IdP 간에만 사용 |
| **SAML 세션** | 두 세션 (Fiori/WebGUI↔IAS, IAS↔Corporate IdP) | 두 세션 (SLS↔IAS, IAS↔Corporate IdP) + X.509 |
| **최종 인증 수단** | SAML Assertion | X.509 인증서 |
| **MFA 발생 위치** | Corporate IdP 로그인 화면 (브라우저) | Corporate IdP 로그인 화면 (SLC 내장 browser) |
| **세션 유지** | 브라우저 세션 | X.509 인증서 유효기간 (기본 12시간) |
